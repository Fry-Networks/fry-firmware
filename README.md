# fry-firmware

Fry Networks embedded firmware for ESP8266/ESP32/ESP32-S3/ESP32-C3 - dVPN endpoint miners with OTA updates.

## Protocol

`PROTOCOL.md` is the byte-identical, shared contract with `fry-app-android`. Neither repo may
change it unilaterally.

## Build

```
pio run -e esp8266
pio run -e esp32
pio run -e esp32s3
pio run -e esp32c3
pio run -e esp32_lab      # esp32 + lab-only serial provisioning commands
pio run -e esp8266_lab    # esp8266 + lab-only serial provisioning commands
pio test -e native        # Unity tests (host, CI only - no compiler is required to build the
                           # board envs themselves)
```

`FRY_API_TOKEN` is read from the environment at build time by `tools/fry_prebuild.py` and baked
into `include/generated/fry_secrets.h`. It is optional; an empty token disables the build-time
bootstrap credential and registration falls back to per-device tokens only.

## Layout

- `include/config.h` — compile-time tunables, all `#ifndef`-guarded.
- `lib/fry_core/` — pure C++ modules with zero Arduino includes: the provisioning state machine,
  OTA boot-fail counter, SOCKS5 greeting/CONNECT parser, a portable SHA-256, and the miner-key /
  device-name identity algorithm. Compiled by both the embedded envs and `pio test -e native`.
- `src/core/` — chip-agnostic logic that still needs Arduino APIs (config store, hardwareapi
  client, OTA client, TLS setup, WiFi-station interface, provisioning-transport interface,
  cross-task trigger hooks).
- `src/esp32/`, `src/esp8266/` — chip-specific implementations behind those `src/core/`
  interfaces: BLE GATT provisioning vs. the SoftAP captive portal, WiFi connect, WireGuard vs.
  SOCKS5 relay, TLS setup. `platformio.ini`'s `build_src_filter` keeps each chip family from
  compiling the other's sources (PlatformIO compiles every `.cpp` under `src/` for every
  environment regardless of `#ifdef` guards — the Library Dependency Finder only gates `lib/`).
- `test/test_provisioning/` — the Unity suite for `lib/fry_core/`.
- `tools/` — host-side serial provisioning, capture, and QA gate scripts; CLI documented in
  `PROTOCOL.md` section 8:
  - `_serialutil.py` — port resolution (by VID:PID or an explicit `--port`) and the
    DTR/RTS-de-asserted-before-open pattern that avoids resetting the board on connect.
  - `provision.py`, `cap.py` — serial provisioning and bounded capture.
  - `flash.sh` — retrying upload to an explicit port.
  - `gate_boot.py` — asserts the boot banner, a well-formed `IOT-<32 hex>` miner key, and no
    crash marker within a bounded window.
  - `gate_wifi.py`, `gate_heap.py` — WiFi-join and heap-floor regression gates.
  - `scan_identity.py` — fails a build that leaks the developer's username or an absolute
    Windows path into a compiled binary.
  - `make_manifest.py` — builds `ota/manifest.json` from the actual built `firmware.bin`s.
- `ota/manifest.json` — generated by `tools/make_manifest.py` (gitignored: it is a per-release
  artifact regenerated with the real version/URLs at release time), consumed per `PROTOCOL.md`
  section 6.

## CI

`.github/workflows/build.yml` builds all four board environments plus the native Unity suite,
uploads each `firmware-<env>.bin` as a build artifact, and — on a `v*` tag — regenerates
`ota/manifest.json` against the tagged binaries and attaches all five files to a GitHub Release.
